# Lesson 3: Channels and Data Flow

## Learning Objective

By the end of this lesson, you should be able to:

- explain what a Nextflow channel carries;
- identify the output of one process;
- identify the input of the next process;
- explain why one process waits for another;
- follow data through a two-process workflow.

## The Main Idea

Nextflow connects processes through data.

One process produces an output, and another process receives that output as an
input.

Lesson 3 follows this path:

```text
upec_context.txt
→ CREATE_CASE_REPORT
→ upec_case_report.txt
→ ADD_REPRODUCIBILITY_NOTE
→ upec_final_report.txt
```

## Open the Workflow

Open:

```text
lessons/03_channels_and_data_flow.nf
```

The workflow contains two processes:

1. `CREATE_CASE_REPORT`
2. `ADD_REPRODUCIBILITY_NOTE`

## Process 1

`CREATE_CASE_REPORT` receives:

```groovy
path context_file
```

It creates:

```groovy
path "upec_case_report.txt", emit: report
```

The keyword `emit` gives the output channel the name `report`.

The output can therefore be referenced as:

```groovy
CREATE_CASE_REPORT.out.report
```

**Nextflow key**

- `path context_file`: receive a file;
- `emit: report`: name the output channel `report`;
- `.out.report`: access the named output from the process.

## Process 2

`ADD_REPRODUCIBILITY_NOTE` receives:

```groovy
path case_report
```

The workflow passes the first process output into the second process:

```groovy
ADD_REPRODUCIBILITY_NOTE(
    CREATE_CASE_REPORT.out.report
)
```

The second process cannot start until the first process creates its output.

This is data-driven execution.


**Command key**

- `-C`: load a configuration file;

- `lessons/03_channels_and_data_flow.nf`: the workflow file;

Both processes should complete successfully:

```text
CREATE_CASE_REPORT (U13824)
ADD_REPRODUCIBILITY_NOTE (final report)
```

## Locate the Final Report

Run:

```bash
# Find the final report under work/.
find work -name upec_final_report.txt -type f
```

**Command key**

- `find`: search for files;
- `work`: the directory to search;
- `-name`: search by filename;
- `upec_final_report.txt`: the filename to find;
- `-type f`: return regular files only.

Display the newest report:

```bash
# Find the newest report and save its path in final_report.
final_report="$(
  find work \
    -name upec_final_report.txt \
    -type f \
    -printf '%T@ %p\n' |
  sort -rn |
  head -n 1 |
  cut -d' ' -f2-
)"

# Display the file stored in final_report.
cat "$final_report"
```

**Output command key**

- `final_report=`: create a shell variable;
- `$(...)`: run the enclosed commands and store the result;
- `-printf '%T@ %p\n'`: print the modification time and file path;
- `|`: pass one command's result to the next command;
- `sort -rn`: sort newest results first;
- `head -n 1`: keep the first result;
- `cut -d' ' -f2-`: remove the timestamp and keep the file path;
- `cat`: display the selected file.

The report should include:

```text
UPEC Teaching Case
SRR21010776
Reproducibility note:
This report was generated by a two-process Nextflow workflow.
```

## What Nextflow Did

Nextflow:

1. placed `upec_context.txt` in a channel;
2. passed the file to `CREATE_CASE_REPORT`;
3. identified `upec_case_report.txt` as an output;
4. passed that output to `ADD_REPRODUCIBILITY_NOTE`;
5. created `upec_final_report.txt`.

The workflow did not need a manual instruction saying which process should run
first. The connected data established the execution order.

## Controlled Connection Error

Open:

```text
lessons/03_channels_and_data_flow.nf
```

Temporarily change:

```groovy
CREATE_CASE_REPORT.out.report
```

to:

```groovy
CREATE_CASE_REPORT.out.missing_report
```

Run the lesson again:

```bash
# Run Lesson 3 with the incorrect output-channel name.
nextflow -C lessons/lesson.config run \
  lessons/03_channels_and_data_flow.nf
```

Read the first clear error message.

Restore:

```groovy
CREATE_CASE_REPORT.out.report
```

Run the workflow again and confirm that both processes succeed:

```bash
# Run Lesson 3 again after restoring the correct connection.
nextflow -C lessons/lesson.config run \
  lessons/03_channels_and_data_flow.nf
```

## Troubleshooting Principle

When a workflow connection fails, check:

1. the upstream process name;
2. the emitted output name;
3. the receiving process input;
4. spelling and capitalization;
5. whether the upstream process completed.
